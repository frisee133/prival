Ты разрабатываешь самостоятельное приложение для группового голосового
общения в духе TeamSpeak. Создай рабочий проект в текущем репозитории.

Цель первой версии — приватное игровое сообщество на одном сервере.
Ориентир для нагрузочной проверки — 20 пользователей в одном канале.
Первый клиент — браузер на ПК. Отдельный следующий этап — Windows-клиент
с глобальным Push-to-Talk, который работает, когда игра в фокусе.
Интерфейс и README — на русском. Используй своё название и оформление.

1. Архитектура

- Клиент — React, TypeScript, Vite и livekit-client.
- API — Node.js, TypeScript, Fastify и livekit-server-sdk.
- Хранение данных — PostgreSQL с миграциями.
- Голос — самостоятельно размещённый LiveKit Server, WebRTC и Opus.
  LiveKit работает как SFU: участник отправляет один аудиопоток серверу,
  сервер пересылает его слушателям.
- API отвечает за аккаунты, роли, приглашения, список каналов, чат и
  модерацию. Голосовой трафик проходит через LiveKit.
- Одному голосовому каналу соответствует одна комната LiveKit. Внутреннее
  имя комнаты вычисляй на сервере из неизменяемого ID канала. Переименование
  канала не должно менять комнату.
- Развёртывание — Docker Compose. Для production используй HTTPS и WSS,
  reverse proxy для приложения и сигналинга и отдельную конфигурацию
  медиапортов. Зафиксируй версии зависимостей и образы контейнеров.
- Проект должен запускаться без аккаунтов и ключей платных облачных
  сервисов. Для MVP достаточно одного узла LiveKit.
- Объём MVP — голос, каналы, текстовый чат и модерация. Видео, демонстрацию
  экрана, запись, мобильные клиенты и совместимость с протоколом TeamSpeak
  оставь за рамками первой версии.

2. Сообщество, каналы и права

- Сделай вход по логину и паролю и регистрацию по приглашениям.
  Первого владельца создай отдельной командой при настройке сервера.
  Для приглашений задай срок действия и ограничение числа использований.
- Роли — владелец, модератор и участник. Раздельно проверяй право видеть
  канал, входить, говорить и модерировать. Закрытые каналы должны
  отсутствовать в списке для пользователей без права просмотра.
- Сделай дерево категорий и голосовых каналов, изменение порядка,
  переименование, список участников и индикаторы говорящих.
  Пользователь находится в одном голосовом канале за раз. При переходе
  отключай публикацию и воспроизведение предыдущего канала, освобождай
  треки и обработчики. Быстрые клики по каналам не должны оставлять
  несколько активных подключений.
- Добавь текстовый чат канала с историей и пагинацией. Проверяй право
  чтения и отправки на сервере, включая подписку на новые сообщения.
- Добавь локальный mute участника и индивидуальную громкость, а также
  серверные действия модератора: отключить право говорить, исключить
  из канала, заблокировать доступ. Храни журнал действий модерации.

3. Голос и Push-to-Talk

- Покажи статусы подключения, переподключения и ошибки. Отдельно обработай
  отказ в доступе к микрофону, отсутствие устройства, отключение гарнитуры
  и блокировку автозапуска звука браузером. Дай кнопку включения звука,
  если для воспроизведения нужно действие пользователя.
- Добавь выбор микрофона, индикатор входного уровня и тест микрофона.
  Выбор устройства вывода включай там, где это поддерживает браузер.
  Для речи используй моно. Дай пользователю настройки доступных браузеру
  эхоподавления, шумоподавления и автоматической регулировки усиления.
- При входе микрофон выключен. Добавь переключатель микрофона, режим
  «Не слышу и не говорю» и Push-to-Talk с настраиваемой клавишей.
  Для веб-версии Push-to-Talk работает при фокусе приложения.
- В Push-to-Talk передавай звук только пока клавиша удерживается.
  При отпускании, потере фокуса, скрытии вкладки, выходе из канала или
  переподключении сразу прекращай передачу. Если пользователь отпустил
  клавишу до окончания асинхронного включения микрофона, звук не должен
  начать передаваться после завершения операции.
- Для Windows-версии переиспользуй веб-интерфейс через Electron. Для
  глобального Push-to-Talk используй проверенный механизм Windows,
  который доставляет и нажатие, и отпускание клавиши без фокуса окна.
  Electron globalShortcut сам по себе не даёт требуемого события
  отпускания. Протестируй удержание и отпускание с игрой в фокусе.

4. Авторизация голосовых комнат

- Выдавай LiveKit JWT через серверный endpoint. Определяй пользователя
  по сессии, проверяй доступ к запрошенному каналу и сам вычисляй
  identity, room и grants. Используй внутренний ID пользователя.
- Токен действует для одной комнаты. Разрешай подписку на звук.
  Публикацию ограничь источником microphone и выдай её только тем,
  у кого есть право говорить. Отключи ненужную публикацию данных.
- Храни LiveKit API secret только на сервере. Используй короткий TTL
  токенов входа, например 60 секунд. При исключении или блокировке
  сначала сохрани запрет и закрой выдачу новых токенов, затем примени
  действие через серверный API LiveKit. При серверном mute меняй
  права публикации на стороне LiveKit.
- Проверь повторный вход со старым и обновлённым токеном. В self-hosted
  LiveKit изменение прав или исключение не отзывает автоматически
  ранее выданные токены. Опиши измеренное окно повторного входа.
  Не выдавай повторное удаление участника за мгновенный отзыв токена.
- Хешируй пароли Argon2id. Для браузерной сессии используй HttpOnly
  cookie, Secure в production и защиту от CSRF. Ограничь частоту попыток
  входа и выпуска токенов. Не записывай аудио, пароли и токены в логи.

5. Развёртывание и диагностика

- Сделай два режима. Локальный — запуск Compose и проверка в двух
  браузерных профилях. Публичный — запуск на Linux с доверенными TLS
  сертификатами, доступным извне IP и настройками firewall.
- В публичном режиме направь HTTPS/WSS через reverse proxy. Для медиа
  настрой отдельные ICE-порты. Для простого конфига рассмотри UDP mux
  на 7882/udp и ICE/TCP на 7881/tcp. Сверь номера с выбранной версией
  и фактическим конфигом. Проверь, какой IP LiveKit объявляет клиентам.
- Настрой встроенный TURN для сетей с ограничениями. Для TURN/TLS
  опиши схему с доступным клиенту 443/tcp. Если веб-прокси уже слушает
  этот порт на том же IP, предусмотрите отдельный IP или L4-маршрутизацию.
  Укажи таблицу портов, домены и назначение каждого порта.
- В README добавь разбор случаев «не подключается», «подключается без
  звука», «звук идёт только в одну сторону» и «из домашней сети
  работает, через мобильную — нет». Объясни, как определить выбранную
  ICE-пару, использование TURN, RTT, джиттер и потери пакетов.
  Для домашнего хостинга объясни, как проверить публичную доступность
  сервера и влияние CGNAT. Опиши сохранение и восстановление базы.

6. Порядок работы и критерии приёмки

- Сначала реализуй минимальный проход от приглашения и входа до
  двустороннего звука у двух пользователей. Затем добавь дерево каналов,
  настройки микрофона, Push-to-Talk, чат и модерацию.
- Добавь .env.example без секретов, Docker Compose, миграции, команду
  создания владельца, конфигурацию LiveKit и README с точными командами.
  Прогони сборку, проверку типов и тесты.
- Проверь двусторонний звук из двух браузерных профилей, затем из двух
  разных сетей. Отдельно проверь TURN/TLS с заблокированным прямым UDP
  и ICE/TCP, подтвердив по статистике, что выбран relay.
- Проверь изоляцию каналов, вход без прав, серверный mute, блокировку
  выдачи токенов, повторный вход со старым токеном, отпускание PTT,
  потерю фокуса, смену гарнитуры и восстановление после обрыва сети.
- Для 20 участников опиши сценарий с несколькими одновременно
  говорящими. Измерь CPU, память, сетевой трафик сервера и потери.
  Если публичного сервера или тестовых клиентов нет, приложи
  воспроизводимые шаги и укажи, какие проверки ещё не запускались.
- В конце покажи команды запуска, что работает, результаты тестов и
  оставшиеся ограничения. Считай сценарий голоса готовым после
  фактической проверки передачи и воспроизведения в обе стороны.

Дополнение к ТЗ

1. Друзья и приватные звонки

Замени пользовательский сценарий с сообществами, деревом каналов и ролями
на список друзей. Главный сценарий: создать профиль с ником, добавить
друга по коду, принять заявку и позвонить. В активный звонок можно
пригласить других друзей.

Добавь входящие и исходящие заявки, статусы «В сети» и «Не беспокоить»,
отклонение звонка, удаление и блокировку друга. Проверяй на сервере,
кто вправе приглашать и подключаться. Используй LiveKit из основного ТЗ:
создавай временную закрытую комнату на каждый звонок и выдавай токены
только допущенным участникам. Один пользователь может участвовать
в одном разговоре одновременно.

2. Локальный профиль без пароля

Вместо регистрации по логину и паролю пользователь вводит только ник.
При первом запуске создай пару ключей на устройстве. Храни закрытый
ключ локально под защитой Windows DPAPI. Для входа подтверждай владение
ключом подписью одноразового запроса сервера.

На сервере храни только данные, необходимые для друзей и звонков:
ID, ник, публичный ключ, заявки, связи друзей и блокировки.
Почту, телефон и пароль не запрашивай. Аудио и историю звонков не сохраняй.

Кнопка «Удалить профиль» завершает сессии и звонки, удаляет серверную
запись и связи с друзьями. После подтверждения сервера удали локальный
ключ, настройки и кэш. Если сервер недоступен, покажи, что удаление
ещё не завершено. Если пользователь просто удалил программу вместе
с локальными данными, ключ теряется, а серверную запись убирает
очистка неактивных профилей по настроенному сроку.

3. Настройки звука

Расширь настройки из основного ТЗ. Добавь проверку микрофона
с прослушиванием своего голоса без отправки звука в звонок, выбор
устройств ввода и вывода, индикатор уровня, отдельную громкость
собеседников и настройку порога активации голосом.

Сделай три режима шумоподавления: выключено, стандартное WebRTC
и усиленное RNNoise. Обрабатывай звук на устройстве. При RNNoise
отключай встроенный шумодав. Эхоподавление и автоусиление регулируются
отдельно. Проверь тихую речь, шум клавиатуры и вентилятора, а также
работу с колонками. Сравни качество речи и нагрузку в каждом режиме.

4. Проверка во время игры

Проверяй Windows-клиент с первого этапа: глобальный Push-to-Talk
должен срабатывать в свёрнутом клиенте, когда игра в фокусе.
Проверь нажатие и отпускание клавиши, первый слог после нажатия
и отсутствие передачи после отпускания. Вне звонка и теста микрофона
освобождай аудиоустройство и останавливай обработку звука.

На одной и той же игровой сцене сравни время кадров, CPU и память
в четырёх режимах: приложение закрыто, приложение в трее без звонка,
звонок со стандартным шумодавом и звонок с RNNoise. Укажи железо,
игру и результаты. Если игровой прогон не выполнен, приложи шаги
для воспроизведения и отметь, что влияние на FPS ещё не измерено.

Дополнительная приёмка: два пользователя на разных ПК создают профили,
добавляют друг друга, принимают звонок и слышат друг друга. Один из них
говорит через PTT с игрой в фокусе, затем удаляет профиль. После этого
профиль пропадает из списка друзей на втором ПК.

Дополнение к ТЗ — доступ из интернета и регистрация в браузере

Работай с текущей сборкой. Сейчас сайт открывается у владельца, но друг
не может зайти, а интерфейс рассчитан на один аккаунт владельца. Сначала
исправь доступ с другого устройства и добавь регистрацию обычных
пользователей. Сайт должен работать в браузере без установки приложения.

1. Доступ к сайту из другой сети

- Воспроизведи проблему и выясни, где она возникает: страница не открывается,
  страница открывается, но API недоступен, или пользователь входит, но
  голосовой звонок не работает. Проверь эти три сценария отдельно.
- Проверь, на каком адресе слушают фронтенд, API и reverse proxy. Убедись,
  что другу передаётся внешний URL, а не localhost или адрес домашней сети.
  Проверь и собранный фронтенд: браузер друга не должен обращаться к API
  или LiveKit по localhost. Для API используй относительный путь на том же
  сайте, если это поддерживает текущая архитектура. Для LiveKit передавай
  внешний адрес WSS, доступный браузеру.
- Настрой HTTPS с доверенным сертификатом, чтобы браузер мог запросить
  доступ к микрофону. Проверь DNS, если используется домен, и правила
  firewall. При домашнем хостинге проверь проброс портов на роутере,
  наличие публичного IP и CGNAT. Если прямой входящий доступ невозможен,
  укажи конкретную причину и рабочую схему для этой сети. Для приватного
  теста можно использовать общую VPN-сеть. Для обычной ссылки без установки
  дополнительного ПО нужен доступный извне хост или подходящая схема
  публикации, которая обеспечивает и сайт, и голос.
- Настрой и проверь медиапорты LiveKit по фактическому конфигу. Если
  веб-страница открылась, отдельно проверь двусторонний звук. Проверь
  подключение через TURN там, где прямой медиатрафик блокируется.
- В README укажи внешний URL или способ его получить, переменные
  окружения, нужные порты и шаги проверки с мобильного интернета.
  Если текущая сеть блокирует публикацию, укажи, на каком шаге и почему.

2. Регистрация для каждого пользователя

- На первом открытии в новом браузерном профиле покажи форму «Создать
  профиль». Пользователь вводит ник, после чего получает собственный ID
  и обычные пользовательские права. Регистрация доступна с главной
  страницы без учётных данных владельца и без кода друга. Права владельца
  назначаются отдельно на сервере.
- Вход без пароля. Генерируй пару ключей в браузере через Web Crypto.
  Храни неэкспортируемый закрытый ключ как CryptoKey в IndexedDB.
  Подтверждай вход подписью одноразового запроса сервера с коротким сроком
  жизни. При повторном открытии сайта в том же браузерном профиле
  пользователь автоматически входит по сохранённому ключу.
- Храни на сервере минимум, необходимый для работы между устройствами:
  ID, ник, публичный ключ, заявки, связи друзей и блокировки. Пароль,
  почта и телефон не требуются. Закрытый ключ остаётся у пользователя.
  Ник может повторяться, личность определяется по ID и ключу.
- Кнопка «Удалить профиль» завершает сессии и звонки, удаляет профиль
  и его связи с сервера. После подтверждения удаления очисти локальный
  ключ и настройки. Друзья должны увидеть исчезновение профиля.
- Если человек просто очистил данные сайта, сменил браузер или удалил
  приложение вместе с его данными, потерянный ключ восстановить нельзя.
  При следующем открытии предложи создать новый профиль, даже если
  выбран тот же ник. Дружбу нужно подтвердить заново через новую заявку.
  Сервер не получает событие очистки браузера или удаления приложения,
  поэтому старую запись убирай по настраиваемому сроку неактивности.
- Код друга используй для добавления в друзья. После регистрации
  пользователь может поделиться своим кодом, принять заявку и позвонить.

3. Приёмка

- Друг с другого компьютера и из другой сети открывает ссылку, создаёт
  свой профиль и после перезагрузки страницы остаётся под своим ником.
  Владелец и друг видят разные профили и имеют разные права.
- Оба добавляют друг друга и проверяют двусторонний звук в браузере.
  Если раздел про друзей ещё не реализован, проверь голос через имеющийся
  механизм и повтори проверку через звонок другу после его добавления.
- Проверь отдельно удаление через кнопку и очистку данных сайта. В первом
  случае профиль исчезает у друзей. Во втором после новой регистрации
  создаётся новый ID, а старые друзья не переносятся.
