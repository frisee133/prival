# Промпт для продолжения разработки «Привала»

Продолжай существующий проект в `C:\Users\frazi\Desktop\Новая папка (2)`. Общайся с пользователем по-русски, простыми словами. Прочитай `СОСТОЯНИЕ ПРОЕКТА.md`, `promnt.txt`, `README.md` и `КАК ПРОВЕРИТЬ С ДРУГОМ.md`. Сверяй описание с текущими файлами. Не начинай реализацию заново.

Продукт называется **Привал** (`prival-voice`, версия 0.2.0). Конечная цель — приложение для Windows для приватного голосового общения с друзьями во время игр. Браузер — текущий тестовый клиент. Главный проход: HTTPS-ссылка → ник и отдельный профиль без пароля → заявка по коду друга → принятие → приватный звонок → двусторонний голос. В разговор можно пригласить других друзей.

Последующие дополнения к исходному ТЗ заменили сообщества, дерево каналов, пароли и чат на друзей, ключи устройства и временные приватные комнаты. Не возвращай отменённые сценарии без новой просьбы пользователя.

## Уже реализовано

- React/TypeScript/Vite; Node.js/Fastify API; PostgreSQL; LiveKit SFU/WebRTC/Opus; Caddy; конфигурации Compose.
- Браузерный Ed25519-профиль с неэкспортируемым CryptoKey в IndexedDB, вход по одноразовой подписи, HttpOnly-сессия. Windows-профиль защищён DPAPI. Разные пользователи могут иметь одинаковый ник.
- Заявки, друзья, блокировки, DND, входящие/исходящие/групповые звонки, ограничение одного активного разговора, серверный допуск в комнаты.
- Удаление профиля и связей после серверного подтверждения, обработка незавершённого удаления, очистка неактивных профилей.
- Устройства ввода/вывода, самопрослушивание, усиление микрофона 0–300%, локальная громкость собеседников, mute/deafen, ручная передача, PTT, VAD, статистика связи.
- Windows Electron-клиент, глобальная PTT через C# Raw Input, трей.
- Прозрачный оверлей участников/говорящих/микрофона, выбор угла и монитора.
- Запуск `Запустить тест.cmd` → `scripts/start-test.ps1` → `scripts/temporary-link.ps1` и локальные службы.

Последнее большое изменение — замена RNNoise/GTCRN на **DeepFilterNet3** через `@workadventure/noise-suppression@0.2.0`. Используются AudioWorklet/WASM, моно 48 кГц. При DFN3 браузерные AGC/шумодав выключены, автоуровень доступен после модели. Варианты: off / standard WebRTC / dfn3. Старые RNNoise/GTCRN-настройки мигрируют на dfn3.

Модель остаётся активной при отпущенной PTT внутри звонка. После неё стоят VAD при его выборе (20 мс look-ahead, 250 мс удержания, плавное затухание), усиление, компрессор и конечный PTT/mute. Отпускание клавиши должно сразу закрывать передачу. Внутренний пауза-гейт DFN3 имеет свой look-ahead. Вне звонка/самопроверки устройство освобождается.

При перегрузке или ошибке модели включается WebRTC с сообщением. Для реального переключения эффектов используется новый захват микрофона; сохраняется состояние конечного PTT. Не подменяй успешную загрузку DFN3 незаметным резервным режимом.

## Ближайшая незавершённая задача

**Надёжно исправить запуск вне Codex, когда `node.exe` отсутствует в PATH.** Пользователь уже дважды получил ошибку и не должен снова выступать единственным проверяющим одного и того же исправления.

В `Invoke-Pinggy` добавлен поиск стандартного Node и `Get-AppxPackage -Name 'OpenAI.CodexPrimaryRuntime*'` → `InstallLocation/dependencies/node/bin/node.exe`. Предыдущая попытка ошибочно искала runtime в LocalAppData. Пакет фактически расположен в Program Files/WindowsApps; не зашивай номер версии.

Но ниже в `temporary-link.ps1` ещё осталось `$node = (Get-Command node.exe).Source` для TURN-моста. В `.local/Запустить.ps1` отдельный fallback в `.cache/codex-runtimes/...`. Исправление не покрывает весь запуск. Создай единый надёжный поиск Node для всех точек, с понятной ошибкой, и используй его последовательно. Учти Windows PowerShell 5.1 и пути с кириллицей/пробелами. Не предполагай, что уже работающие службы доказывают холодный старт.

Проверь запуск в среде обычного CMD/PowerShell без Node в PATH, затем повторный запуск; публичный HTTPS-адрес должен появляться последней строкой при успехе. Тест `tests/temporary-link.ps1` сам по себе проверяет helper/кодировки/ANSI/stdout/тайм-аут, а не полный пользовательский запуск. Предыдущие заявления о полном устранении ошибки были преждевременными.

## Сеть и условия пользователя

У пользователя нет VPS или домена. Временная ссылка через ретранслятор уже согласована — не спрашивай согласие повторно. Используются HTTP-туннель Pinggy для сайта/WSS и отдельный TCP-туннель для TURN. Бесплатная сессия примерно час, адрес меняется. Не считай старый URL действующим без проверки.

Локальный сайт/API: 127.0.0.1:18080; DB:15432; LiveKit:17881; прокси сигналинга:17880; шлюз туннеля:18880; TURN-мост:19444. VPN HTTPS:26.69.72.39:18443; локальный TURN/TLS на этом VPN-интерфейсе:443; ICE/TCP:17882, ICE/UDP:17900–18000. Нативная схема владельца пока зависит от Radmin-интерфейса и локального CA, хотя другу VPN для публичного теста не нужна.

Секреты лежат в `.env`, `.local/preview.env`, LiveKit/CA-конфигурациях — не печатай их. Не удаляй базы и `.local`. Подготовленный стенд не переносится одним Git-архивом: `.local` и `dist` игнорируются.

Pinggy ранее обрывал большие файлы около конца ответа с ERR_CONTENT_LENGTH_MISMATCH. Для его доменов `client/dfn-assets.ts` загружает сжатую WASM и модель проверяемыми Range-частями по 256 КиБ, 4 одновременно, с ограниченными повторами. `scripts/compress-audio.mjs` создаёт gzip WASM после сборки, Fastify поддерживает preCompressed. Все модели раздаются локальным сервером. После этого публичный браузерный прогон прошёл.

Native Pinggy CLI использует `scripts/pinggy-command.mjs`: stdout/stderr направлены в файлы, ожидание ограничено. Не возвращай бесконечное ожидание EOF через перехваченный pipe. PS1 с кириллицей сохраняй UTF-8 с BOM. `-Renew` пересобирает локальные шлюзы, но может повторно использовать ещё живые туннели и не гарантирует новый час сессии.

## Проверки и предел доказательств

Ранее прошли сборка, 5 модульных проверок, API-тесты, Chrome с двумя профилями и настоящим декодированием двустороннего аудио, публичный relay/TCP, VPN relay/TLS на 443, загрузка DFN3 и обработка синтетического шума, два вида удаления профиля. В Electron проверены профиль DPAPI, звук и PTT со скрытым окном. Оверлей проверен программно, включая WS_EX_TRANSPARENT; подготовленный EXE запускался.

Это в основном два клиента на одном физическом компьютере, включая маршрут через внешний relay. Не называй это приёмкой двумя людьми на разных ПК или голосом через мобильную сеть. Естественная речь, первые слоги на гарнитуре, игровой PTT, реальный сквозной щелчок по оверлею, эксклюзивный экран и FPS ещё требуют проверки. Автопереключение DFN3 тестировалось в том числе искусственным сигналом перегрузки; это не игровой бенчмарк.

Подготовленный клиент: `dist/windows/Привал/Привал.exe`, передавать всю папку. Сервер в `server.json`; ключи браузера и приложения разные. Обновление адреса требует полного выхода через трей. Сборка поверх работающего EXE однажды получила EPERM на DLL — закрывай приложение корректно или используй отдельную папку сборки, не убивай пользовательский разговор без причины.

Команды проекта: `npm run build`, `npm run typecheck`, `npm test`, `npm run test:audio`, `npm run test:api`, `npm run test:browser`, `npm run windows:build`. Интеграционным тестам нужен сервер; `TEST_ORIGIN`, `TEST_PUBLIC_RELAY=1`, `TEST_DESKTOP=1`, `TEST_DESKTOP_EXE` задают режимы. Не предполагая npm в PATH, сначала определи доступный Node/npm.

После исправления запуска обнови инструкцию, дай пользователю точные шаги и пройди приёмку с другом. Затем исправляй проблемы по вердикту и готовь постоянную публикацию. Честно сообщай, что проверено, что ещё нет, и текущую точку остановки. Продолжай необходимые обратимые действия самостоятельно без повторных запросов разрешения.
