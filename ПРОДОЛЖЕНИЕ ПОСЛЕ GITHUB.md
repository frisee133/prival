# Продолжение после загрузки проекта с GitHub

Это снимок разработки «Привала», версия 0.2.0. Известная ближайшая задача — закончить единый поиск Node.js в скриптах запуска. Полная передача работы описана в `СОСТОЯНИЕ ПРОЕКТА.md`, готовый запрос следующему исполнителю — в `ПРОМПТ ДЛЯ ПРОДОЛЖЕНИЯ.md`.

В репозиторий входят исходники приложения, миграции, конфигурации Docker Compose, тесты и документы. Скрипт `.local/Запустить.ps1` сохранён как исходный код подготовленного Windows-стенда. База, пароли, пользовательские ключи, CA, локальные конфигурации с секретами, скачанные серверные программы и собранный EXE исключены.

На исходном ПК исключённые файлы остаются на диске. На другом компьютере их нет: двойной щелчок по `Запустить тест.cmd` сразу после клонирования не создаёт весь нативный стенд.

## Базовая подготовка на другом ПК

Потребуются Node.js не ниже 24.12 с npm, Git и работающий Docker Engine с Compose. Для сборки Windows-клиента также нужны Windows и компилятор .NET Framework, используемый `scripts/windows.mjs`.

В каталоге клонированного проекта:

```powershell
npm ci
node scripts/setup.mjs
npm run build
docker compose up -d --build
```

Скрипт setup создаёт новый `.env` со случайными локальными секретами и сохраняет существующий файл, если он уже есть. В этом Compose-варианте сайт открывается по `http://localhost:3000`. Публичная публикация и Windows-стенд на 18080 описаны отдельно в README; их параметры не следует смешивать.

Полноценный запуск Compose на новом ПК ещё требует проверки. Ранее голосовые интеграционные проверки проходили преимущественно на нативном Windows-стенде.

Для сборки клиентской Windows-папки:

```powershell
npm run windows:build
```

Закрой ранее запущенный EXE перед повторной сборкой в ту же папку: загруженные DLL могут быть заблокированы. После сборки проверь адрес в `dist/windows/Привал/server.json`; для другого компьютера нужен доступный ему HTTPS-сервер.

Не загружай `.env`, базы, ключи и каталоги CA в последующие коммиты. Репозиторий содержит `.env.example` без секретов.
